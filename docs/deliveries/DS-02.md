## Implemented behavior

Templates validate artifact/selection schema, asset, time_base, complete evidence
timeline, selected detections and status linkage. They include only selected
frames, all 17 COCO points ordered, `review_status: unreviewed`, null annotator ID,
null coordinates and unreviewed visibility. No model coordinate/confidence is
copied into the reference. Selected remains heuristic, requiring human target
confirmation; template generation does not verify the athlete's identity.

Evaluation validates the full artifact and annotations independently before
joining exact asset/time_base/frame/PTS/display dimensions. References may be an
ordered frame subset, but each frame must contain all 17 ordered keypoints.
Reviewed inputs require annotator ID and explicit visibility for every point.
Unknown fields, repeated IDs/names, incorrect types, invalid geometry and any
nonfinite JSON fail explicitly with ValueError (including Pydantic's subclass).

For reviewed references, `reference_points = matched_points + missing_predictions`.
Mean/median Euclidean pixel errors use only matched visible references; coverage
and missing counts accompany them. Null keypoints, absent linked detections and
null reference detection ID keep visible points in the denominator as missing
predictions. The evaluator never guesses another player, interpolates, clamps,
zero-fills or filters by model-native confidence/visibility/presence. Finite
outside-image predictions retain their error without implying visibility.

Unreviewed inputs return not_evaluated, zero counts and null metrics. Zero visible
reviewed references also return not_evaluated with null coverage/errors. Visible
references with zero predictions return computed, coverage 0, errors null and
all references missing. Reason codes distinguish these cases. Arithmetic avoids
overflow when a finite mean/median exists and rejects an unrepresentable distance
instead of emitting Infinity. Inputs are not mutated. `validation_ref` stays null.

## Limits and head follow-up

- These tests establish implementation properties, not athlete accuracy,
  biomechanical validity or human review. No real video was evaluated by DS-02.
- Only pooled keypoint errors and output coverage are computed. No uncertainty,
  PCK/OKS, false-positive/identity metric, phase detection or acceptance threshold.
  The protocol requests future reporting by athlete/phase/articulation and an
  independent reference; this module does not implement that study.
- Template frames depend on successful selection. Representative annotation must
  also include independently sampled failure frames, using the same format with
  null/absent detection links. The protocol gives this procedure explicitly.
- JSON textual duplicate keys must be rejected by the caller's parser before a
  dict is built; overwritten keys cannot be recovered at this dictionary API.
- Exact serialized time_base equality is deliberate; equivalent fractions with
  different strings are rejected rather than silently normalized.
- Model-specific detection correspondences require human review outside this
  format. `reviewed` and annotator ID are assertions, not cryptographic evidence
  that an independent annotation workflow actually happened.
- Head owns compatibility testing against actual CV-02/BE-03 outputs, runtime and
  any private real-video test. No merge, push, deployment, model download or
  scientific acceptance occurred in DS-02.
- No pose-to-M01 bridge, ideal angle, coaching, posture score, scientific
  acceptance threshold or public metric release. P1 reports remain unchanged
  with public `value: null`.
