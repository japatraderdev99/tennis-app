## Entrega e interfaces

- `src/tennis_backend/contracts/`: modelos Pydantic estritos `MediaManifest`,
  `ResearchInput`, `ResearchResult`, `PublicReport`, `ErrorEnvelope`, exportados
  diretamente de `tennis_backend.contracts`, junto de `can_transition`.
- `schemas/`: cinco JSON Schemas Draft 2020-12 reproduzíveis e README com o uso,
  invariantes em Python, diferenças de semântica de inteiros e limites.
- `tests/contracts/`: fixtures sintéticas positivas/negativas, gerador reproduzível,
  testes estruturais, condicionais por status, referências, pico/séries e matriz
  exaustiva de transições. `fixtures/index.json` descreve cada exemplo e separa
  validade do modelo de validade do schema.

`model_validate(dict)`/`model_validate_json(text)` são os pontos de validação.
Inteiros não aceitam bool/float/string; números rejeitam bool/string/NaN/Infinity;
objetos tipados proíbem extras, e nullable não significa opcional.
`can_transition` aceita recursos `asset` e `analysis`; desconhecidos retornam falso.
Nenhuma alteração de dependências ou interface congelada foi necessária.

## Validação executada

Ambiente: Python 3.12.1; Pydantic 2.14.2, pytest 8.4.2 e jsonschema 4.26.0,
instalados conforme `uv.lock` existente. `pyproject.toml` e `uv.lock` preservados.

```sh
uv sync --frozen --offline --cache-dir /private/tmp/tennis-uv-cache
uv run --frozen --offline --cache-dir /private/tmp/tennis-uv-cache python tests/contracts/build_fixtures.py
uv run --frozen --offline --cache-dir /private/tmp/tennis-uv-cache python -m tennis_backend.contracts.generate_schemas
uv run --frozen --offline --cache-dir /private/tmp/tennis-uv-cache pytest tests/contracts -q
```

Resultado final: **486 testes passaram**, sem rede, mídia real ou outros módulos.
Os testes conferem os schemas contra regeneração e `check_schema`, fazem validação
Python/JSON dos exemplos e cobrem coerção, não finitos, campos obrigatórios/extras,
nulabilidade pública, contagens, evidência, geometrias representáveis, PTS,
estados e diagnósticos de erro. Fixtures inválidas intencionais nunca são usadas
como dados válidos da aplicação.

## Decisões e limites para integração

- Observações ausentes/pontos nulos/segmentos degenerados são aceitos como estrutura
  de entrada; DS-01 deve retornar `insufficient_evidence` e preservar série parcial.
  Rejeitar esses inputs aqui impediria o diagnóstico explícito exigido pelo contrato.
- Série computada exige >=2 amostras, índices consecutivos dentro da fase, PTS
  crescentes e evidência/valor correspondendo ao primeiro máximo. Nenhum cálculo
  geométrico foi implementado nesta frente. Ângulos ficam em [0,180].
- Manifesto conserva PTS inicial não zero e negativo. Tempos são PTS vezes razão
  exata, com tolerância de duas ULPs apenas para arredondamento de float.
  PTS ausente/não monótono é aceito com motivo; a entrada de pesquisa recusa esse
  timeline. Não há obrigação de nomes específicos de motivos além de snake_case.
- Contagens, relações entre campos e referências internas são validadas em Python.
  Integração deve verificar o mesmo asset/timeline/PTS entre os artefatos, cobertura
  da fase e evidências do relatório resolvidas ao manifesto: modelos isolados não
  recebem todos esses contextos. `is_demo=true` depende do produtor no relatório.
- JSON Schema não distingue `1` de `1.0` como o validador estrito nem representa
  todos os joins/aritmética; usar Pydantic nos limites. Ver `schemas/README.md`.
- Erros rejeitam valores não JSON/não finitos, caminhos absolutos reconhecíveis e
  campos textuais de stderr. A sanitização semântica de prosa arbitrária continua
  sendo responsabilidade do produtor. Não existe alegação de redator universal.
- Modelos devem ser revalidados após mutação; `model_construct`/cópias sem validação
  são escapes do Pydantic e não fazem parte do fluxo de aceitação.
- Nenhuma mídia, cálculo M01, API, banco, inferência de pose ou validação
  biomecânica foi implementada. Estes testes comprovam propriedades de software
  com dados fabricados; não são testes de integração nem validação em atletas.

Bloqueios: nenhum. Desvios de interface: nenhum. Aceitação pelo head permanece
separada desta entrega local.
