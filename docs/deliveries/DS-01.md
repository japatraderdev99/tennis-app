## Public interfaces

```python
from tennis_backend.metrics import compute_m01, normalized_to_display_pixels

compute_m01(payload: dict) -> dict
normalized_to_display_pixels(x, y, width, height) -> tuple[float, float]
```

`compute_m01` validates the frozen input using private strict Pydantic models,
rejecting unknown/missing fields, boolean integers/coordinates, numeric strings,
nonfinite coordinates, non-JSON numeric objects, invalid side/provenance, invalid
rational time base, nonconsecutive indices, absent/nonincreasing/duplicate PTS,
duplicate/out-of-timeline observations, mismatched observation PTS, reversed
windows and endpoints absent from the timeline. Malformed input raises
`ValueError` (including Pydantic `ValidationError`, its subclass).

An otherwise valid one-frame phase returns `insufficient_evidence` with
`insufficient_phase_frames`; it does not raise for inadequate sample coverage.
Missing observations, explicit null joints and vector norm <=1e-12 pixels also
return `insufficient_evidence`. They suppress the entire window's peak/evidence,
while preserving all window rows, including null-valued failed rows and raw valid
measurements elsewhere. Invalid evidence outside the window does not invalidate
window coverage; structural validation still applies to the entire input.

Series rows follow timeline order and include both window endpoints. Original
frame indices and integer PTS are retained, with no index/FPS timing substitution
or resampling. Observation order is irrelevant. Exact computed-value ties select
the earliest PTS. Input is not mutated, and output provenance is copied.

Stable reason vocabulary:

- `missing_observation`
- `missing_hip`, `missing_knee`, `missing_ankle`
- `degenerate_hip_knee`, `degenerate_ankle_knee`
- `insufficient_phase_frames`

Global reasons are deduplicated in first-appearance timeline order; missing-joint
reasons use hip/knee/ankle order. `insufficient_phase_frames`, when present, is
last. Computed results and usable rows have empty reason lists.

The coordinate helper multiplies x by width and y by height independently. It
requires positive integer dimensions and finite JSON numeric coordinates and
output; finite coordinates outside [0,1] are allowed without clamping. It does
not apply rotation, SAR correction or calibration: callers must supply the same
already corrected display plane used for annotation.

## Limits and integration handoff

Interface deviations: none. No dependency/interface change requested. One-frame
window classification is explicitly recorded above for head integration review.

This is only deterministic, unfiltered projected 2D arithmetic on supplied
synthetic/manual landmarks. It does not establish anatomical 3D, human annotation
quality, temporal resolution, measurement uncertainty or biomechanical validity.
Floating-point arithmetic follows the prescribed acos/clamp formula; ordinary
roundoff applies near collinear configurations. Uniform-scale invariance holds
only while segments remain above the absolute degeneracy threshold.

`status="computed"` and its numeric value belong exclusively to the INTERNAL
research artifact. No public report is built here. Head must validate the joined
input/output against BE-01 models, resolve evidence to the media asset/PTS, and
keep the product-facing metric value null. Builder tests are not integration
acceptance. `validation_ref` remains null and uncertainty remains not established.

No video inference, data collection, model, filter, interpolation, M02/M03/H01,
progress history, ideal-angle threshold, coaching, frontend, cloud, HTTP service,
publication, merge or push is included.
